## 1 · 令牌 v0.4

完整令牌：`mp/miniprogram/styles/tokens.wxss`

### 颜色

主色 **硬地场蓝 `#2E4FD8`**。语义色红绿橙（赢/输/待处理）。

**单一用途的约束色**（别处禁用）：

| 色 | 唯一用途 |
|---|---|
| 网球黄 `--c-serve` | 发球方指示点（双打=四人中的当前发球者） |
| 微信绿 `--c-wx` | 微信原生能力入口（支付、手机号授权） |

**头像色板刻意是一组冷色**，不含绿/红/橙 ——
一个绿色头像会被误读成「这个人赢了」。

> **这条约束的是画面，不只是色板。** 头像已经从「色块」改成「平台备的一组图」
> （`User.avatarUrl`），那组图同样不能以绿/红/橙为主色 —— 换了载体，
> 误读的机制一模一样。色块现在的角色是**兜底**：图没备好、旧数据、
> 或者球场信号差拉不下来时，回落到昵称首字加色块。出图规格见 `image-spec.md`。

报名状态 → 颜色是**固定映射**，不可临时改：
待编排 / 候补 / 候补转正 = 橙，已确认 = 绿，已退款 / 作废 = 灰。

**全站不做深色模式。** `app.json` 的 `darkmode` 为 `false`，样式里也没有
`prefers-color-scheme` 分支 —— 注册页的浅蓝底和赞助商底图都是固定值，
翻色会让浅色卡片嵌深色控件，底图也跟不着色。`npm run check` 守着这条。

### 三个组件配方

**赛事等级 A/B/C** —— 用主色三档强度，**不新开色相**：

| 等级 | 样式 |
|---|---|
| A | 实心 `--c-brand` + 白字 |
| B | `--c-brand-weak` 底 + `--c-brand` 字 |
| C | 透明 + `--c-line` 描边 + `--c-ink-3` 字 |

> 色轮已无空位（绿=赢+微信、红=输/危险、橙=进行中、黄=发球、紫青=头像）。
> 更要紧的是 **A/B/C 是有序不是并列** —— 三个色相只能表达「三种」，
> 表达不了「三档」。

**待办角标** —— 复用 `--c-live` 橙（语义就是「有事待处理」），不新增颜色。

**空值「—」** —— `--c-ink-3`，**字号与真值一致**。两条规矩：
必须与加载态形态不同（空值是实心字符，加载是骨架条）；
字号不能缩，否则真值出来那一刻整块会跳。

### 控件高度

```
--h-control: 88rpx   /* 输入框、分段、副按钮 —— 44pt，iOS 最小点击区 */
--h-cta:     96rpx   /* 主按钮 */
```

### 两端：颜色共用一套，尺寸各一套

小程序（`mp/`，rpx）和网页后台（`adminweb/`，px）是两个端：

| | 小程序 | 网页后台 |
|---|---|---|
| 单位 | rpx（750rpx = 屏宽） | px |
| 令牌在哪 | `mp/miniprogram/styles/tokens.wxss` | `design/admin/_style.txt` |
| 控件高 | `--h-control: 88rpx` = 44pt | `--h-ctl: 36px` |
| 深色模式 | 不做 | 不做 |

**颜色令牌两端必须一致** —— 同一个产品，A/B/C 等级、赢绿输红、待处理橙、
头像色板都是同一套值。改色要两边一起改。

**尺寸令牌两端刻意不一致。** 88rpx 那条的理由是 iOS 最小点击区，是给**手指**
定的；鼠标指针精度高得多，桌面上照搬 44pt 会让整个后台又空又幼稚。
所以后台 36px，不是「没对齐设计系统」，是对齐了不同的输入设备。

> 推论：**「球场边可点元素不低于 88rpx」那条（下面第 8 条）不约束后台** ——
> 后台压根不在球场边用。

### 八条排版规则

1. **双打组合名**：宽容器一行 `A / B`，窄容器两行堆叠，**绝不只截断其中一个**
   （单打只有一个名字，不适用）。
   375pt 设备上名字列可用 244pt，超过就堆叠 —— 中文姓名永远触发不了，
   只有长英文名会
2. **抢七比分用上标** `7⁷ 6⁵`，不用 `7-6 (7-5)`
3. **发球指示是网球黄的唯一用途**
4. **水平可信度 < 60% 显示为区间** `3.2–3.8`，用 en dash 不用连字符。
   刻度是 **NTRP 2.0–5.0**，和自评同一把尺子（`PRD.md` §8）——
   两个值在界面上并排，刻度不同没人读得懂。
   *（这条原来举的例子是 `6.8–7.6`，不在 NTRP 量程内，已改正。
   区间要用到的「可信度」字段随算法一起加，第一版没有。）*
5. **满员不是错误状态** —— 用橙不用红，按钮变「加入候补」不灰掉
6. **头像色不能用语义色**
7. **倒计时必须写明超时后果** —— 「23:41」无意义，「超时释放名额 23:41」才有
8. **球场边使用的所有可点元素不低于 88rpx** —— 约束 P2 与 P4 两条路径

## 2 · 赛事封面

组织者建赛时**可选**上传一张封面，用在赛事卡和赛事详情页顶部。

| | |
|---|---|
| 出图 | **1125 × 630** JPEG（比例 750:420） |
| 大小 | ≤ 120 KB |
| 存放 | **云存储**，不进包 —— 每场赛事一张，包内放不下 |
| 裁切 | `aspectFill`，主体须落在中间 60% |

**没传封面不是错误状态。** 用主色渐变加巨大的赛事名首字水印兜底 ——
放灰色占位图会让那场赛事看起来像坏了。

照片上压一层渐变（顶 .46 → 底 .82），白字和主色按钮才站得住。
`--c-on-photo` 是照片上文字的唯一取值。

> 注册页**不再**用这套 —— 它换成了浅蓝纯色底，遮罩已拆掉（见 §11）。
> 封面是这一套遮罩现在唯一的使用者。

> 等级标签 `tier.c` 在照片上有**唯一变体**：描边从 `--c-line` 改成半透明白 ——
> 浅灰描边压在深色遮罩上看不见。

## 3 · 注册页底图

注册页是**唯一一张有品牌底图的页**，形式是「纯色天空 + 底部赞助商条」，
**不是**一张铺满的照片。

| | |
|---|---|
| 页面底色 | `--c-sky: #98C5FE` |
| 赞助商条 | `images/register-sponsors.jpg` · 750 × 330 · 54 KB |
| 母版 | `design/assets/register-bg-source-lt.jpg`（750 × 1600） |

母版上半 55% 是空白浅蓝，九宫格 logo 在 **55%~72%**、品牌字在 **76%~84%**。
表单卡（四字段 + 主按钮）本身就要 1100rpx 上下，**整张铺满时卡片正好落在
logo 上**，赞助商全被盖住。所以拆开用：

- 上半的浅蓝 → 页面纯色底（任何屏幕比例都不会裁）
- 中间的九宫格 logo → 裁成 750×330 一条，**当内容排在表单后面**，跟着滚
- 底下两行品牌字 → **不要**，连它一起裁整条会到 520rpx，压在表单下面太长

页面上也没有 LJTENNIS 小字和「你正在报名什么」那行上下文 ——
标题只留**「上场之前」**一行。

`--c-sky` 从母版逐位取色，和图里的蓝必须完全一致，否则接缝会露出来。
**换底图就重新取色。**

> **待办：母版只有 750px 宽（@1x）。** 赞助商条 1:1 铺满 750rpx，@3x 上
> logo 会发虚，`npm run check` 会一直警告到换成 2250px 宽的原图为止。
