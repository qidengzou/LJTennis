# 小程序图片规格

## 一、单位换算

小程序设计稿**固定 750rpx 宽**，不管什么设备。`750rpx = 屏幕宽度`。

在 375pt 的基准屏上：`1rpx = 0.5pt`。所以：

```
图片像素宽 = rpx 宽 × DPR ÷ 2
```

| 一个 200rpx 宽的元素 | 需要的图片像素 |
|---|---|
| @2x（iPhone SE / 8） | 200px |
| @3x（iPhone Pro / 多数安卓旗舰） | **300px** |

**记法：按 rpx 数值的 1.5 倍出图，就覆盖了 @3x。**

安卓还有 2.75x / 3.5x 的机型，但 @3x 出图已经够用 —— 再高只是浪费包体积。

## 二、各类图的规格

| 用途 | 显示尺寸 | 出图（@3x） | 格式 | 大小上限 |
|---|---|---|---|---|
| **tabBar 图标** | — | **81 × 81 px** | PNG | 10 KB |
| 导航栏 / 行内图标 | 40–48rpx | 72 px | SVG 优先 | 5 KB |
| 头像 · 小 | 64rpx | 96 px | JPEG | 15 KB |
| 头像 · 大 | 96–120rpx | 180 px | JPEG | 25 KB |
| 列表缩略图 | 200 × 150rpx | 300 × 225 | JPEG | 40 KB |
| 卡片大图 | 750 × 420rpx | 1125 × 630 | JPEG | 120 KB |
| **注册页赞助商条** | 满宽 750rpx | **2250 × 1560**（现为 750×520） | JPEG | 150 KB |
| 分享卡片 | 比例 **5:4** | 500 × 400 | JPEG | 128 KB（微信硬限制） |
| 空态插画 | 200–300rpx | 450 px | SVG 优先 | 20 KB |

> **tabBar 图标是硬规格**：官方要求 81×81px，且**不支持网络图片和 base64**，必须放在包内。

> **赞助商条 2250 宽** 的来源：它按 1:1 铺满 750rpx，@3x 就是 2250 物理像素。
> 现有母版只有 750px（@1x），logo 会发虚，`npm run check` 会一直警告到换图为止。

## 三、格式怎么选

| 格式 | 用在哪 | 注意 |
|---|---|---|
| **JPEG** | 照片、有渐变有噪点的图 | 质量 72–78 就够，再高看不出来 |
| **PNG** | 需要透明、纯色图形、tabBar 图标 | **照片绝对不要存 PNG** —— 体积会大 10 倍以上 |
| **SVG** | 图标、简单插画 | `<image>` 组件支持，但不支持 SVG 内的脚本和外部引用 |
| **WebP** | 想再省 25–35% 体积 | 需基础库 2.9+，开发者工具预览偶尔不显示 |

## 四、包体积约束

| | 上限 |
|---|---|
| 主包 | **2 MB** |
| 单个分包 | 2 MB |
| 全部合计 | 20 MB |

**图片是唯一会真正吃掉这个额度的东西** —— 代码通常只有几百 KB。

放包内的判断标准：

- ✅ **必须首屏立刻出现**：tabBar 图标、空态插画、注册页赞助商条
- ❌ 其余一律放**云存储 / CDN**：赛事封面、选手头像、场地照片

云存储的图可以直接在 `<image>` 里用 `cloud://` 路径（基础库 2.2.3+），不用先换临时链接。

## 五、`mode` 属性

| mode | 行为 | 用在哪 |
|---|---|---|
| `scaleToFill` | 拉伸填满，**会变形** | 基本不用（这是默认值，要小心） |
| `aspectFit` | 完整显示，留白 | 必须看到全图时（证书、签表全览） |
| **`aspectFill`** | **填满并裁切** | 背景图、封面图 |
| `widthFix` | 宽固定，高按比例 | 富文本里的图 |
| `heightFix` | 高固定，宽按比例 | 横向滚动列表 |
| `top` `bottom` `left` `right` | 按锚点裁切 | **不缩放**，是原尺寸裁，慎用 |

### aspectFill 的裁切数学

图会被缩放到**刚好盖住**容器，多出来的部分**从中心裁掉**。

```
缩放比 = max(容器宽/图宽, 容器高/图高)
```

手机屏比例范围：**0.56（iPhone SE）～ 0.46（Pro Max）**

所以一张 2:3（0.667）的图，在 Pro Max 上左右各会被裁掉约 **15%**。

> **结论：不要指望找到 0.46 的源图**（图库里基本没有，那个比例只有手机截图才有）。
> 正确做法是**选 2:3 或 9:16 的源图，自己裁到 0.46**，同时确认主体落在中间 60% 以内。

## 六、当前注册页底图

注册页**不再用摄影底图**。改成「纯色天空 + 底部赞助商条」：

| | |
|---|---|
| 页面底色 | `--c-sky: #98C5FE`，写在 `styles/tokens.wxss` |
| 赞助商条 | `mp/miniprogram/images/register-sponsors.jpg` · 750 × 520 · JPEG · 80 KB |
| 母版 | `design/assets/register-bg-source-lt.jpg`（750 × 1600，包外） |
| 上一版 | 摄影底图 `register-bg.jpg`（Unsplash，1080×2341）已删；留档见 `design/assets/register-bg-source.jpg` |

**为什么不整张铺满。** 母版上半部 0–55% 是空白浅蓝，九宫格 logo 在
**55%~72%**、品牌字在 **76%~84%**。注册表单卡（四个字段 + 主按钮）本身就要
1100rpx 上下，铺满底图时卡片正好落在 logo 上，赞助商全被盖住——那张图存在的
意义就没了。所以拆开用：

- **上半部的浅蓝**→ 页面 `background: var(--c-sky)`（纯色，任何屏幕比例都不会裁）
- **下半部的 logo + 品牌字**→ 裁成 750×520 的一条，**当内容排在表单后面**，跟着滚

`--c-sky` 是从母版逐位取的（`sips -c 6 6 --cropOffset … -s format bmp` 读像素），
必须和图里的蓝完全一致，否则图和纯色之间会有一道接缝。**换底图就重新取色。**

**重新出图（可完全复现）：**

```bash
sips -c 520 750 --cropOffset 850 0 design/assets/register-bg-source-lt.jpg \
  --out mp/miniprogram/images/register-sponsors.jpg -s formatOptions 88
```

> `--cropOffset` 的两个参数是 **offsetY offsetX，从左上角算起**（不是从中心）。
> 850 是 logo 上方留 40px 蓝，520 高刚好切到品牌字下方 20px。

### 待办：换 @3x 母版

现在这张母版是 **750px 宽 = @1x**。赞助商条按 1:1 铺满 750rpx，在 @2x/@3x 手机上
要放大 2~3 倍，logo 和 `™` 会发虚。`npm run check` 会为此报一条警告，宽度到
**2250px** 才消。这是素材问题，不是代码问题——向主办方要一张 2250×4800 的原图，
用同样的比例重裁即可（offset 2550、高 1560）。

## 七、自动检查

```bash
cd mp && node scripts/check-images.js
```

会扫 `miniprogram/images/`，检查：扩展名与真实格式是否一致、尺寸是否超规格、单文件与总体积是否超预算。

---

> ⚠️ **用 `sips` 处理本地图时（图标、头像、缩略图）：它会改写输入文件，哪怕带了 `--out`。永远先 `cp` 一份再处理。**
