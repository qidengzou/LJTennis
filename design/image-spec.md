# 小程序图片规格

## 一、单位换算

小程序设计稿**固定 750rpx 宽**，不管什么设备。`750rpx = 屏幕宽度`。

在 375pt 的基准屏上：`1rpx = 0.5pt`。所以：

```
图片像素宽 = rpx 宽 × DPR ÷ 2
```

| 一个 200rpx 宽的元素 | 需要的图片像素 |
|---|---|
| @2x（iPhone SE / 8） | 200px |
| @3x（iPhone Pro / 多数安卓旗舰） | **300px** |

**记法：按 rpx 数值的 1.5 倍出图，就覆盖了 @3x。**

安卓还有 2.75x / 3.5x 的机型，但 @3x 出图已经够用 —— 再高只是浪费包体积。

## 二、各类图的规格

| 用途 | 显示尺寸 | 出图（@3x） | 格式 | 大小上限 |
|---|---|---|---|---|
| **tabBar 图标** | — | **81 × 81 px** | PNG | 10 KB |
| 导航栏 / 行内图标 | 40–48rpx | 72 px | SVG 优先 | 5 KB |
| 头像 · 小 | 64rpx | 96 px | JPEG | 15 KB |
| 头像 · 大 | 96–120rpx | 180 px | JPEG | 25 KB |
| 列表缩略图 | 200 × 150rpx | 300 × 225 | JPEG | 40 KB |
| 卡片大图 | 750 × 420rpx | 1125 × 630 | JPEG | 120 KB |
| **全屏背景** | 满屏 | **1290 × 2796** | JPEG | 400 KB |
| 分享卡片 | 比例 **5:4** | 500 × 400 | JPEG | 128 KB（微信硬限制） |
| 空态插画 | 200–300rpx | 450 px | SVG 优先 | 20 KB |

> **tabBar 图标是硬规格**：官方要求 81×81px，且**不支持网络图片和 base64**，必须放在包内。

> **全屏背景 1290×2796** 的来源：目前最高屏 iPhone 16 Pro Max 是 430×932pt @3x。

## 三、格式怎么选

| 格式 | 用在哪 | 注意 |
|---|---|---|
| **JPEG** | 照片、有渐变有噪点的图 | 质量 72–78 就够，再高看不出来 |
| **PNG** | 需要透明、纯色图形、tabBar 图标 | **照片绝对不要存 PNG** —— 体积会大 10 倍以上 |
| **SVG** | 图标、简单插画 | `<image>` 组件支持，但不支持 SVG 内的脚本和外部引用 |
| **WebP** | 想再省 25–35% 体积 | 需基础库 2.9+，开发者工具预览偶尔不显示 |

## 四、包体积约束

| | 上限 |
|---|---|
| 主包 | **2 MB** |
| 单个分包 | 2 MB |
| 全部合计 | 20 MB |

**图片是唯一会真正吃掉这个额度的东西** —— 代码通常只有几百 KB。

放包内的判断标准：

- ✅ **必须首屏立刻出现**：tabBar 图标、空态插画、注册背景
- ❌ 其余一律放**云存储 / CDN**：赛事封面、选手头像、场地照片

云存储的图可以直接在 `<image>` 里用 `cloud://` 路径（基础库 2.2.3+），不用先换临时链接。

## 五、`mode` 属性

| mode | 行为 | 用在哪 |
|---|---|---|
| `scaleToFill` | 拉伸填满，**会变形** | 基本不用（这是默认值，要小心） |
| `aspectFit` | 完整显示，留白 | 必须看到全图时（证书、签表全览） |
| **`aspectFill`** | **填满并裁切** | 背景图、封面图 |
| `widthFix` | 宽固定，高按比例 | 富文本里的图 |
| `heightFix` | 高固定，宽按比例 | 横向滚动列表 |
| `top` `bottom` `left` `right` | 按锚点裁切 | **不缩放**，是原尺寸裁，慎用 |

### aspectFill 的裁切数学

图会被缩放到**刚好盖住**容器，多出来的部分**从中心裁掉**。

```
缩放比 = max(容器宽/图宽, 容器高/图高)
```

手机屏比例范围：**0.56（iPhone SE）～ 0.46（Pro Max）**

所以一张 2:3（0.667）的图，在 Pro Max 上左右各会被裁掉约 **15%**。

> **结论：不要指望找到 0.46 的源图**（图库里基本没有，那个比例只有手机截图才有）。
> 正确做法是**选 2:3 或 9:16 的源图，自己裁到 0.46**，同时确认主体落在中间 60% 以内。

**重新出图（可完全复现）：**

```bash
curl -sL -o mp/miniprogram/images/register-bg.jpg \
  "https://images.unsplash.com/photo-1714840961998-8d6c02ace00b\
?w=1080&h=2341&fit=crop&crop=focalpoint&fp-x=0.53&fp-y=0.5&q=62&fm=jpg"
```

### 为什么是这几个参数

| 参数 | 理由 |
|---|---|
| `crop=focalpoint` + `fp-x=0.53` | 裁到 0.461 要切掉 30.9% 宽度。**居中切会把球（0.83）和影子右缘（0.87）切掉**，右移到 0.53 后可见范围到 0.876，全部保住，只损失左侧空场地 |
| `fp-y=0.5` | 纵向不裁（母版比目标"更宽"，只裁横向），此参数实际不生效 |
| `w=1080` 而非 1290 | 1290 在任何质量档下都 ≥500KB。底图上压着遮罩，**降分辨率比降质量划算** —— 1080 在 1290 屏上放大 1.19×，肉眼不可辨；而降质量会让球场纹理出块 |
| `q=62` | 实测 1080 宽下 q=62 → 384KB，q=70 → 448KB（超预算）。遮罩会盖掉大部分压缩痕迹 |
| CDN 生成而非本地裁 | imgix **从未压缩的母版直接出图，全程只编码一次**。本地方案是"下载已编码的 JPEG → 解码 → 裁 → 缩 → 再编码"，属第二代编码，天空和场地这种大面积渐变最容易出色带 |

> ⚠️ 不要用 `crop=entropy`（imgix 自动找信息量最大区域）—— 结果不可复现，换个时间跑可能裁到别处。

## 七、自动检查

```bash
cd mp && node scripts/check-images.js
```

会扫 `miniprogram/images/`，检查：扩展名与真实格式是否一致、尺寸是否超规格、单文件与总体积是否超预算。
